The loop

Four moves, every campaign.

One command. Every number in the report comes from a real, seeded, reproducible run.

01

Inject

Seven AST operator families flip >= to >, + to -, negate branches, nudge boundary constants. Twelve prompt perturbations strip roles, rename schema keys, corrupt delimiters.

Isolate

Every bug runs against your suite in its own sandboxed copy of the project - parallel and timeout-guarded. Runaway mutants get killed, not your machine.

Score

Killed vs. survived over a frozen bank. The mutation score is the number your line-coverage report was hiding: how many real behavior changes your assertions actually notice.

Heal

For each survivor, differential probing finds an input where original and mutant disagree, then synthesizes a hardened assertion - re-verified before it is written, never guessed.

One file is the entire integration.

SyntraceAI is a local developer tool, not a hosted service. There is no account, no upload and no API key: it reads your source, mutates temporary copies, runs your suite against them, and deletes them.

If your layout is not app/ + tests/, drop syntrace_target.json in your project root. exclude lists modules you do not want mutated; prompt_templates points at your prompt module and switches on the 12 prompt perturbations - leave it null for a code-only campaign.

Honest by design

The uncomfortable numbers are the ones we print.

A benchmark you cannot interrogate is a benchmark you cannot trust. Three commitments hold the whole tool up.

local only

Offline. No account. No upload.

No model calls, no API key, no telemetry. It reads your source, mutates temporary copies, runs your suite against them and deletes them. Your code never leaves your machine.

reported

Equivalent mutants are reported, not hidden.

Provable cases are excluded from the bank up front. Unprovable ones are surfaced as unhealable survivors rather than silently capping the score. No verified discriminating input, no test.

byte-stable

Deterministic reports you can diff.

Same seed, same bank, same scores - on any machine, at any parallelism. Timeouts and errors are labeled, not laundered, and every number on this page is read back from the committed report JSON.

What it found

Four assertions humanize never had.

Run exhaustively against humanize 4.16.0, the engine wrote - tests its own suite lacked. These four pin unit-scaling thresholds nobody had asserted - found by differential probing, re-verified in both project copies before being emitted.

humanize.number.intwordverified
assert humanize.number.intword(1e+27, '%.1f') == '1.0 octillion'

The octillion entry in intword's power table. Its 311 vendored tests execute the function; none of them asserted this magnitude.

humanize.number.intwordverified
assert humanize.number.intword(1e+18, '%.1f') == '1.0 quintillion'

The quintillion entry, one rung down. A mutated power-table constant changed the output and the suite stayed green.

humanize.filesize.naturalsizeverified
assert humanize.filesize.naturalsize(1e+33, False, False, '%.1f') == '1000.0 QB'

The top of the unit ladder, past the last suffix. Reached through the module's own public API, not a guessed literal.

humanize.number.metricverified
assert humanize.number.metric(1e+33, '', 3) == '1.00 x 10³³'

The fall-through past the last SI prefix into scientific notation - a formatting branch the suite executed but never checked.

Evidence, not endorsement: these are generated tests from a reproducible run against a library we did not write, committed in this repo. The remaining survivors are listed in the report as unhealable, with the reason.
